Usage · a worked session and the full reference

Card to catalogue.One shoot, step by step.

This page walks through a shoot from start to finish: copy the card, let a vision model judge every frame, check its calls yourself, sort the frames into folders, and import them into Capture One. Each step shows the command to type and what it prints back. You type the commands in Terminal (in Applications › Utilities). The examples come from a small Leica M11-P shoot; yours will have its own numbers.

60 Install

Install cull, then pick the model that judges your frames.

$ brew install jefflaplante/tap/cull

Without Homebrew, download the universal binary (Apple silicon and Intel) from the latest release:

$ curl -fsSL https://github.com/jefflaplante/cull/releases/latest/download/cull_macos_universal.tar.gz | tar -xz && sudo mv cull_macos_universal/cull /usr/local/bin/

Or build it from source with Go 1.26 or newer:

$ git clone https://github.com/jefflaplante/cull && cd cull && make build   # writes bin/cull
  • Only one step costs anything. Copying, scanning, the review sheet, calibration, sorting and the Capture One scripts all run on your Mac for free. cull judge is the one command that sends frames to an AI model.
  • You choose that model with --backend (a flag: an option typed after the command, starting with --). The table shows what each choice needs and what it costs.
  • Options you’d type every time can go in a settings file, ~/.cull. The ~ means your home folder, so this is the file .cull in /Users/you. A line such as backend = claude-code saves typing it. Finder hides files whose names start with a dot, so open it from Terminal: touch ~/.cull && open -e ~/.cull opens it in TextEdit. See Your defaults.
  • Capture One features need macOS, because Capture One is controlled through AppleScript. cull version shows which version you installed.

125 Offload

Copy the card, with every file checked against the original.

$ cull offload /Volumes/LEICA\ M ~/Pictures --name "Forest portraits" --location "Forest Park, Portland"

This copies the card mounted at /Volumes/LEICA M into a new shoot folder inside ~/Pictures, your Pictures folder. The backslash tells Terminal that the space is part of the card’s name. Your card will have its own name: type the command up to that point, then drag the card’s icon from Finder into the Terminal window and its path is filled in for you.

Offload prints the name of the folder it made. Shoot folder names are long, so the rest of this page saves yours under a short name, $SHOOT. Type this once in each Terminal window, with your folder’s name (or type SHOOT= and drag the folder in). Keep the quotes, here and around "$SHOOT" later: they hold a name with spaces together.

$ SHOOT=~/Pictures/"2025-12-28 Forest portraits"
  • It plans before it writes. It names the folder <date> <name>, counts what there is to copy, and stops before copying anything if the folder name is taken or the drive is too full.
  • Every copy is checked against the card. As each file is read, cull computes a fingerprint of it (a SHA-256 checksum). After writing, it reads the copy back from the drive itself, not from memory, and compares fingerprints. Only a copy that matches is kept. A plain Finder copy checks nothing.
  • “Safe to format the card” appears only when every file has been checked on every destination. If a copy is interrupted, run the same command again: it copies only what is missing.
  • The folder date comes from the photos. If your camera’s clock was wrong, set it yourself with --date 2026-10-02.
  • Then it scans the new folder, for free. It reads each frame’s preview, finds faces, sets blank frames aside, and groups near-identical frames (bursts) into sets.

250 Judge

Check the price first, then let the model judge every frame.AI

$ cull judge --estimate "$SHOOT"
estimate: 17 frames × ~6k in / ~1k out tokens ≈ 102000 in / 17000 out ≈ $0.37 at list price (claude-sonnet-5-5)
ranking ≈ 2 call(s) for 2 set(s) already found, $0.06 at list price (at most: frames judged cull leave their sets)
$ cull judge --backend claude-code "$SHOOT"
  • The estimate is free and calls nothing. AI services charge by the token, roughly a measure of how much image and text the model reads and writes. A frame uses about 6,000 tokens in and 1,000 out, which comes to about 2 cents at list price. Bursts are compared in one extra call per set, and the estimate prices those too.
  • What the model looks at: the whole frame, scaled down for context, and a crop of the subject at full resolution, where sharpness is judged. The subject is the face cull found, or, with no face, what the model picks out as meant to be sharp.
  • What it reports: how sharp the subject is, the exposure (with a suggested correction), the composition (with a suggested crop), whether eyes are open, and a few content keywords.
  • The model only describes; fixed rules decide. Missed focus or motion blur is culled. Soft focus goes to review. Exposure and composition never cull a frame: they get a suggested fix. The same assessment always gets the same verdict, so you can tune the rules later without paying to judge again.
  • Bursts are ranked. Near-identical frames form a set, and the model compares each set side by side. The best three keep their verdicts; the rest go to review.
  • Stopping is safe. If you press Ctrl-C, or a cost limit or your plan’s allowance stops the run, type the same command again (leaving out --fresh, if you used it): it skips the frames already judged and carries on.
What each verdict means
KeepSharp where it matters. Any exposure or crop note is a suggestion for the edit.
ReviewWorth a look: soft focus, closed eyes, clipped highlights, or not among the best of its burst.
CullMissed focus or motion blur, or a blank frame such as a lens-cap shot.
  • How long it takes: roughly 5–20 seconds a frame, unattended. A 1,000-frame shoot runs for a few hours on a Claude subscription while you do something else. The model is the slow part, not your Mac.
  • Sidecars are written as it goes. Each DNG gets a small .xmp file beside it with the verdict as a colour label and keywords, which Capture One reads on import. --no-xmp turns that off.

500 Review

Look through the verdicts, and change any you disagree with.

$ cull review "$SHOOT"
  • A contact sheet opens in your browser. It runs on your own Mac; nothing is uploaded. Each frame shows the crop the model judged, its verdict and its reasons, so you can see why it decided what it did.
  • It’s driven from the keyboard (keys in the table). Each label is saved the moment you press the key, to the shoot’s labels file and to the frame’s sidecar. Closing the tab loses nothing.
  • Your label beats the model’s everywhere after this: in the sidecars, when frames are sorted into folders, and in Capture One. cull also keeps the model’s verdict, so it can measure how often the two of you agree (the next step).
  • Bursts are boxed together, with the number of keepers in the box’s header. Press − or = to keep fewer or more of the best-ranked frames.

1000 Tune

See how closely it matches your judgement, then adjust its rules.

$ cull calibrate "$SHOOT"
$ cull decide --keep-best 3 --outranked cull --raw-clipped review "$SHOOT"

Only you know how strict to be. Once you’ve labelled some frames in review, calibrate compares your labels with cull’s verdicts, and decide applies new settings in seconds, without judging anything again.

  1. Label a sample in cull review, pressing K (keep) or C (cull); stars alone don’t count. Start with at least 30 frames, including some you would throw away. The more you label, the more the rates mean: with 30 frames a single false cull is several percent, while a few hundred give a rate you can trust. cull status counts how many you’ve done.
  2. Run cull calibrate and read the false-cull rate first: how many frames you’d keep that cull would have thrown away. That’s the number that matters most; under 1% is a good target.
  3. Read the grid below it. Each row replays the rules under one combination of three settings and shows what would have happened: false culls, culls caught (frames you’d cull that it culled), culls missed (frames you’d cull that it kept) and how much went to review. A * marks rows under 1% false culls.
  4. Pick a starred row: the one that catches the most culls, or the one that sends the least to review if you’d rather check fewer frames. Rows that send less to review usually let more of your culls through as keeps, so check the missed column too.
  5. Apply it with cull decide, typing that row’s three values as flags, as in the command above. Run calibrate again to confirm: your row is now marked ← current.
Part of a grid (4 of 20 rows)

* 2       review    review          3 (0.5%)      33      60   49.5%  ← current
* 3       cull      review          6 (0.9%)      80      95   39.8%
  2       cull      review         16 (2.5%)     115      60   39.8%
* 4       cull      ignore          4 (0.6%)      67     151   22.3%
  • The three settings: --keep-best is how many frames of each burst keep their verdict; --outranked is what happens to the rest of the burst (sent to review, or culled); --raw-clipped is whether blown highlights send a frame to review or are ignored.
  • In this example (a shoot judged with --keep-best 2), the second row catches more than twice as many culls, 80 instead of 33, and sends less to review: 40% instead of 50%. The costs: false culls go from 3 to 6, still under 1%, and more of your culls stay keeps, 95 instead of 60.
  • The settings are saved with the shoot, so later commands on it keep them. Once they’ve held up on your next labelled shoot as well, make them the default for future shoots in your settings file ~/.cull, one per line:
    keep-best = 3
    outranked = cull

2000 Before import

Add keywords and sort into folders, before you import.

$ cull tag --event "Fall session" --keyword family "$SHOOT"
event: Fall session
location: Forest Park, Portland
keywords: family
saved; rewrite the sidecars with: cull decide "Pictures/2025-12-28 Forest portraits"
$ cull decide --sort "$SHOOT"
writing sidecars: 17 files
sorting frames into keep/, review/ and cull/: 17 frames
decided 17 frame(s); no decision changed; sorted 17 into keep/, review/ and cull/, 0 back into the shoot folder
  • cull tag sets keywords for the whole shoot: project, event, location and any extras. You can also give them when you copy the card, as the offload step did with --location. The next decide writes them into every sidecar.
  • The sidecars already exist, written while judging. decide --sort refreshes them (adding your tags), then moves the files. Each sidecar carries:
    • your stars;
    • a colour label: Green keep, Yellow review, Red cull;
    • the keyword cull:keep (or cull:review, cull:cull);
    • the model’s content keywords, such as portrait, smile and woodpile;
    • your tags, as plain words and as paths such as event|Fall session. Capture One shows the paths as nested keywords. (Lightroom Classic ignores sidecars for DNG files, so none of this reaches it.)
  • --sort moves each DNG with its sidecar into keep/, review/ or cull/ inside the shoot folder. Then import just keep/ and review/. If you’d rather keep one folder, --sort=culls moves only the culls aside, into cull/.
  • Sort before importing, not after. Capture One and Lightroom lose track of files that move once they’re in a catalogue. Every move is recorded, and cull restore puts every frame back where it was.
  • Before you format the card, cull offload --verify "$SHOOT" checks every copy against its fingerprint once more. It finds the frames in their new folders too.

4000 Capture One

Send changes made after import into Capture One.

With Capture One open on the catalogue, run a read-only check that cull and Capture One agree on how images are named. The | passes cull’s script straight to osascript, the Mac’s built-in AppleScript runner:

$ cull apply-c1 --probe "$SHOOT" | osascript -

Then save the script and read it (a dry run), and apply it:

$ cull apply-c1 --exposure "$SHOOT" > apply.applescript
$ cull apply-c1 --run --exposure "$SHOOT"
  • Capture One reads a sidecar only when it imports the file. Changes made after import need another route. apply-c1 writes an AppleScript for the open Capture One document, covering labels you changed, keywords added with cull tag, and exposure.
  • It sets colour tags, keywords and your stars on the images already in the catalogue. Ratings are set only on frames you rated, so ratings you made in Capture One stay.
  • Without --run it only prints the script, so you can read every line before anything changes. The > apply.applescript saves that printout to a file you can open in any text editor.
  • --exposure applies the EV you set in review. It also applies the model’s suggestion, but only where Capture One’s exposure is still at its default, so your own edits stay. --crop works the same way for suggested crops.
  • Why exposure needs a script: Capture One 16.7 ignores the exposure value in a sidecar on import (tested). Stars, colour labels and keywords in sidecars do work.
  • Your DNGs are never modified. Only the sidecars and the catalogue change.

B Reference

Every command and every flag, with examples.

Conventions. <dir> is a shoot folder, the one holding the DNGs. Each shoot has one report, cull-report.json, the source of truth that every command reads and updates. Beside it sit cull-labels.jsonl (your labels), cull-offload.jsonl (the checksums taken at copy time) and cull-review/ (the contact sheet). Flags may go before or after the folder. Durations use Go syntax (90s, 2m, 1m30s). A boolean that defaults to true is turned off with --flag=false.

Exit status is 0 on success and 1 on any error, with the message on stderr after error:. Progress and summaries go to stderr, so 2>&1 | tee captures a run. status and version print to stdout. Every command also has --help, which shows its flags in sections with examples; --help-all adds the tuning and experimental flags.

What costs money: only judge calls a model, and it takes --estimate to price the run for free first. Everything else is local and free.

Global flags

Accepted by every command.

Recursion. Without -r, only the DNGs directly in <dir> are processed. With it, subfolders are walked too, and there is still one report for the whole tree, at the top. Folders named keep, review or cull (and the culled folder of older versions) are skipped at any depth, so frames that cull moved are never processed twice. That also means a folder you named review is never scanned. Moves happen inside each frame’s own subfolder.

Your defaults. Any of these flags, and most of every command’s, can be given a default of your own in ~/.cull: see Your defaults: ~/.cull for the format and which value wins.

Help is in sections. cull <command> --help groups a command’s flags under headings: the command’s own flags first, then Policy flags (the keep, review and cull rules, stored in the report), Backend flags, and Sidecar and folder flags where they apply. --help-all also prints Tuning flags (image preparation, checkpoints, batch polling) and Experimental flags (features not yet measured against labels). The reference below follows the same grouping.

The live view. On an interactive terminal, every step that can take a while shows as a line of its own: the offload copy and its final flush, scan, judge, ranking, writing sidecars, sorting and moving frames, restoring them, rendering the review sheet, a batch’s preparation, upload and wait, and apply-c1 --run. Each active line has a spinner and the time it has run, so a step that is working but has nothing new to count still visibly moves. Piped output, -q or --plain give plain lines instead, which still say what each quiet step is doing when it starts.

Flags

-o, --reportpath · default <dir>/cull-report.json

Reads and writes the report at this path. A relative path is taken from the current directory, not from <dir>. The labels log defaults to the folder holding the report.

Use it to keep two runs of one shoot side by side, for example two backends, then compare them with calibrate --compare. Pass the same -o to every later command for that run. With judge and decide, such a report leaves the shoot’s sidecars alone unless you type --no-xmp=false.

$ cull judge --backend claude-code -o cc.json ~/Pictures/"2026-10-02 Smith wedding"
$ cull judge --backend openai --model qwen3-vl-8b -o local.json ~/Pictures/"2026-10-02 Smith wedding"
$ cull calibrate --compare cc.json local.json
-r, --recursivebool

Also processes subfolders, with one report for the whole tree (see above). Useful for a trip with one folder per day.

$ cull judge --estimate -r ~/Pictures/2026-10-Iceland
-q, --quietbool

Prints only warnings, errors and the final summary. Use it in scripts and cron jobs. A dry run’s plan still prints, since it is the whole output.

-v, --verbosebool

Adds per-stage and per-call detail. For offload that is one line per file with its hash prefix. For judge it covers the focus target chosen, tokens and cost per call.

$ cull offload -v /Volumes/LEICA\ M ~/Pictures --name "Smith wedding"
M1103817.DNG → M1103817.DNG (sha256 3f9a2c1e…)
--debugbool

Everything -v shows, plus backend events, request sizes and the model’s raw answers. Credentials are never printed. Use it to see exactly what a model said when a verdict looks wrong.

--log-levelquiet | normal | verbose | debug

The long form of -q, -v and --debug, handy in shell aliases. Combining it with them, or giving two of them, is an error rather than a guess.

--plainbool

Plain lines even on a terminal, with no live view. Use it when you want scrollback, or with tee.

$ cull judge --plain --backend claude-code ~/Pictures/"2026-10-02 Smith wedding" 2>&1 | tee judge.log
--help-allbool

Lists every flag. --help shows a command’s everyday flags in sections; --help-all adds the tuning and experimental ones too. It works with no folder given, on the command or on cull itself.

$ cull judge --help-all
--versionbool

Prints cull version v0.1.0. Same as cull version.

Your defaults: ~/.cull

A dotfile of flag defaults: what you’d otherwise type on every run.

Each line is a flag’s name (without the dashes), =, and its value. # starts a comment. Lines under a [command] header apply to that command only; the lines above any header apply to every command that has the flag. Booleans take true or false; a repeatable flag such as keyword takes one line per value; quotes around a value are optional.

# ~/.cull
backend = claude-code     # judge on your Claude subscription
keep-best = 3
outranked = cull

[review]
sort = all                # re-sort by your labels when the review server stops

Managing it

Create or edit it with any text editor: there’s nothing to install or register.

See what it changed. Every run that takes a value from it prints one line first, for example defaults from /Users/you/.cull: --keep-best 3 --outranked cull. cull judge --estimate <dir> is a free way to check, without changing anything.

Turn it off for one run with CULL_CONFIG=/dev/null, or use another file with CULL_CONFIG=~/cull-weddings, for different kinds of work.

Mistakes are flagged, not ignored. A name no command has (a typo) prints a warning and is skipped. A value that doesn’t fit the flag, such as keep-best = lots, or a malformed line, stops the command with the file and line.

What it can’t set. One-off and risky flags are refused with a warning, so you always type them on purpose: yes, fresh, force, rerank, run, probe, verify, dry-run, estimate, prepare, clear-cache, overwrite-xmp, report, help, version, and the verbosity flags quiet, verbose, debug and log-level.

Old keys still work, with a warning. sort = true reads as sort = all, write-xmp = false as no-xmp = true, and move-culled = true as sort = culls; a leftover resume line is ignored. Each prints a deprecation notice and never stops the run. See Changed in v0.2.0.

$ CULL_CONFIG=/dev/null cull judge --estimate ~/Pictures/"2026-10-02 Smith wedding"   # without your defaults

Precedence: which value wins

From strongest to weakest:

1. A flag you type on the command line always wins.

2. The shoot’s stored policy and backend. The stored policy covers the decision rules and set grouping only:

  • it covers keep-best, outranked, eyes-closed, raw-clipped, raw-clip-threshold, junk, review-below-sharpness, cull-max-sharpness, min-crop-area, seq-gap and seq-look;
  • every judge, decide and review --sort saves the full policy it used in the shoot’s cull-report.json;
  • decide, calibrate, judge (continuing a report) and review --sort start from it, so tuning done on one shoot stays with that shoot;
  • the backend, model and effort of a judged shoot are stored too, and a continuing judge uses them in place of ~/.cull.

3. ~/.cull: a [command] section first, then the lines above any header.

4. The built-in default.

A fresh cull judgeThere’s no stored policy yet: typed flags, then ~/.cull, then the defaults. The result becomes the shoot’s stored policy.
A cull judge that continues--backend, --model and --effort come from the report the shoot was judged with, not ~/.cull, so a set is ranked by the model that judged it.
cull judge --freshReplaces the report, so the backend comes from the flag you type, then ~/.cull, then the default. A different backend or model typed against an existing report is refused, with the flags that continue the run.
File says 3, shoot says 2With keep-best = 3 in ~/.cull and 2 stored in the shoot, cull decide uses 2, and its note policy from the report: --keep-best 2 says so. Type --keep-best 3 to change the shoot, which then stores 3.
Back to a defaultType it: cull decide --keep-best 3 <dir>. Leaving a flag off keeps the stored value.

To see a shoot’s stored policy, look at "policy" and "seq" in its cull-report.json, for example with jq '.policy, .seq' cull-report.json.

cull offload

Copies DNGs off one or more cards into a new shoot folder, verifying every copy against the card before it gets its name.

cull offload <card>... <dest> [--name N] [--date YYYY-MM-DD] [--backup ROOT] [--rename PATTERN]
cull offload --verify <shoot folder>

What it copies: every .dng file (any case) anywhere on each card. It skips system clutter (.fseventsd, .Spotlight-V100, ._ AppleDouble files), never follows symlinks, and ignores JPEGs. The last argument is the destination root, and every other argument is a card. Cards are only ever read.

How each file is copied. The card is read once, in 4 MiB pieces, with SHA-256 computed during that read. The bytes go to a hidden temporary file in each destination, written uncached. The temp file is fsynced and dropped from the page cache; a check confirms none of it is left in memory. It is then read back from the disk and compared with the hash.

Only a match gets its real name, by link(2), which refuses to replace an existing file. Failed reads and verifies are retried twice, after 1 s and 3 s. A full disk stops at once. Ctrl-C finishes the file in flight. At the end, one F_FULLFSYNC per drive flushes the drive’s own write cache.

“Safe to format the card” appears only when every file verified on every destination, nothing failed, nothing was skipped unverified, and the flushes succeeded. Otherwise the last line says NOT safe to format the card, explains why, and the exit status is 1. Re-running the same command copies only what is missing.

The shoot folder is <dest>/<YYYY-MM-DD> <name>. The date is --date, or else the earliest EXIF capture time across all cards in the run. The plan names the frame the date came from, so a wrong camera clock is visible before anything is written. It is one folder per run unless you split it into events (below), so to add a second card to yesterday’s folder, pass the same --date and --name.

The plan refuses before writing anything when the copy won’t fit (it needs the bytes, plus 1%, plus 512 MiB, per volume), or when two cards hold the same file name. Same-name files are common with two bodies or a wrapped counter, and --rename keeps both.

After a safe copy it scans the new folder, with cull scan’s defaults: previews, EXIF, faces, blank frames and sets. That is free, and leaves the folder ready for judge --estimate. The shoot tags (--project, --event, --location, --keyword) are stored in the folder’s report right after the copy, with or without the scan. A dry run stores nothing, and says so.

Where and what

--namestring

The shoot name: the folder becomes "<date> <name>", and the name fills {name} in --rename. Without it the folder is just the date. /, \ and : are refused.

--dateYYYY-MM-DD · default earliest capture date

Sets the folder date, and {date}. Use it when the camera clock is wrong, or to add another card to an existing folder. A card can hold several shoots; the date of the earliest frame names the whole run.

On the card this was tested with, all 992 frames were stamped within ten minutes of each other on a day they weren’t shot, from a clock set wrong.

--backuproot folder

--renamepattern · default camera names

Renames files as they are copied. The tokens are:

{date}: the folder date as 20261002;
{name}: --name with spaces as underscores;
{orig}: the camera’s file stem, such as M1104211;
{n}: a counter;
{n:W}: the counter zero-padded to W digits.

The pattern must contain {n} or {orig}, so names stay unique. The extension is kept and upper-cased. The counter continues across every card in the run, and across later runs into the same folder, because it starts after the highest number already there.

Events

--splitbool

Puts each event on the card into its own numbered shoot folder, such as 2026-10-02 Smith wedding 1 and … 2, so each imports into Capture One or Lightroom as its own set. A new event starts wherever capture time jumps by more than --split-gap, or the day changes, and each folder is dated by its own frames. Each event gets its own manifest, scan and report. Free space is checked for all of them together. If only one event is found, the folder isn’t numbered.

Gaps survive a clock set to the wrong time, because the intervals stay the same. A clock that wasn’t running at all doesn’t: when 90% or more of consecutive frames share a timestamp, --split refuses and suggests --split-at. The card this was tested on had 969 of 991.

$ cull offload --dry-run --split /Volumes/LEICA\ M ~/Pictures --name "Smith wedding"
--split-gapduration · default 2h

With --split, the capture-time gap that starts a new event. A wedding with a break between ceremony and reception might want 45m; a travel day 4h.

--split-atfile names, comma-separated

Starts a new event at each named file, in camera order, whatever the clock says. Name the first frame of each later event, with or without .DNG; find them in the camera’s playback or a contact sheet. A name that isn’t on the card is refused rather than guessed. Can’t be combined with --split.

$ cull offload --split-at M1103426,M1103838 /Volumes/LEICA\ M ~/Pictures --name "Trip"

Checking

--dry-runbool

Prints the plan and exits, writing nothing. The plan shows the folder, where its date came from, the destinations, how many files will be copied and skipped, and every refusal. It still exits 1 if the copy would be refused, so it works as a pre-flight check in a script.

--verifybool

Takes one shoot folder and re-hashes every file recorded in its cull-offload.jsonl, reading uncached from the disk. It also looks in keep/, review/ and cull/ (and an older culled folder), so sorted frames are found. It reports anything missing or different, and any DNG that cull never verified. Exit status 1 if anything is wrong.

Run it right before formatting the card. It re-reads 67 GB, so it takes as long as reading the drive.

$ cull offload --verify ~/Pictures/"2026-10-02 Smith wedding"
992 verified, 0 missing or different
--checksumbool

Decides whether a file is already copied by hashing both sides instead of comparing name, size and time. That is slow: it re-reads every already-present file from the card.

Use it when the plan says files are “already there but never checked against the card”. That happens with files copied by Finder or another tool, which have no manifest line, so cull won’t call the card safe to format.

$ cull offload --checksum /Volumes/LEICA\ M ~/Pictures --name "Smith wedding" --date 2026-10-02
--no-scanbool

Stops after copying. Use it when you will judge elsewhere, or when the folder already holds a judged report: the scan would refuse to overwrite it, and the run would end with status 1 even though the copy was safe.

The manifest. cull-offload.jsonl in each destination gets one JSON line per file, appended and synced only after that file verified everywhere. The fields are src, orig, name, size, mtime, sha256 and at. Keep it: it is what --verify checks against, and what tells a re-run which skipped files are proven.

cull scan

Extracts and measures every preview without calling a model. It writes only the report, so it is free and safe.

cull scan [--save-inputs DIR] [--raw-clip] <dir>

scan runs the judging pipeline up to the model call and stops there. For each frame it records:

The preview: the largest embedded JPEG, found by walking the DNG’s TIFF structure. On an M11-P that is 9504×6320, full resolution. EXIF: camera, lens, focal length, capture time and orientation. Exposure statistics and the junk class. Faces: pigo face detection at 2000 px, with a quality score Q; a confident face (Q ≥ 80) becomes the focus target, and its eyes are located. Sharpness measures at the subject and the eyes, and a “where focus landed” tile. The look: an 8×8 colour fingerprint, used to group near-identical frames into sets.

Use it to check a camera’s previews before spending money, to label a shoot in review without judging it, or with --save-inputs to see exactly what the model would be sent. Sidecars and files are never touched. offload runs it automatically after a safe copy.

It won’t throw away paid work. If the folder’s report already holds model assessments, scan refuses unless you pass --fresh. If the report records frames moved by --sort, it always refuses: run cull restore first. Stored tags always carry over.

Examples

$ cull scan ~/Pictures/"2026-10-02 Smith wedding"
previews: long edge min/median/max = 9504/9504/9504 px; sources: tiff-ifd=17; orientation: 1=3 8=14; faces: 9/17, eyes measured on 9
$ cull scan --save-inputs ~/Desktop/what-the-model-sees ~/Pictures/"2026-10-02 Smith wedding"

What is measured

--raw-clipbool · default false on scan, true on judge

Also decodes the raw data (pure Go, lossless JPEG) and measures the share of samples at the sensor’s white level, at about 0.8 s per frame. The preview overstates clipping because it is a tone-mapped JPEG. On one frame it showed 3.89% clipped where the raw had 0.50%. It works on striped lossless-JPEG DNGs: the M11-P, M10, M10-R and M (Typ 240), and Pentax and Ricoh bodies. Uncompressed or tiled DNGs (Q2, SL2, phones, Adobe DNG Converter output) fall back to the preview, with a note.

$ cull scan --raw-clip ~/Pictures/"2026-10-02 Smith wedding"
--face-min-qfloat · default 80

How confident a face detection must be before it becomes the focus target. In testing, every detection with Q ≥ 100 was a real face, while turned or tilted faces topped out at 28–51, alongside false detections in the bokeh. Below the threshold, judge asks the model to locate the subject instead.

Among confident faces, the largest one scoring at least half the best Q wins: the bride, not a guest in the background. Raise it if bokeh is being cropped as a “face”; lower it for small, frontal faces.

$ cull scan --face-min-q 100 ~/Pictures/"2026-10-02 Smith wedding"
--tilesint · default 1

“Where focus landed” tiles per frame: 384 px native-resolution crops from the most in-focus structure, with sensor noise subtracted. They answer “where is the plane of focus”, not “is the subject sharp”, so they are sent to the model only when there is no subject crop. 0 skips them.

--landed-with-subjectbool

Also sends landed tiles when a subject crop exists. Off by default for a measured reason: with both in view, the model compared skin with crisp in-plane fabric or hair, and culled four sharp faces.

--min-preview-edgepx · default 1500

If the largest embedded preview’s long edge is below this, scan asks exiftool (if installed) for a bigger one. A preview still too small is flagged “focus judgement unreliable”. M11-P previews are 9504 px. Some cameras embed only 160 px or 320 px, such as the M9 and the M (Typ 240), and scan is how you find out.

$ cull scan --min-preview-edge 3000 ~/Pictures/old-m9-shoot
--max-edgepx · default 1024

The long edge of the downscaled full frame sent for context. Sharpness is judged on the native-resolution crops, so this mainly sets cost: 1024 instead of 1568 cut input tokens 16%, with verdicts within run-to-run noise. In scan it only affects --save-inputs.

Sets

--seq-gap, --seq-lookduration, float · default 1m0s, 0.08

How frames are grouped into sets; see the policy flags. scan only groups the frames. Ranking needs a model.

Output

--save-inputsdir

Writes exactly what the evaluate call would receive, per frame: <frame>.full.jpg, <frame>.subject.jpg, <frame>.landed-1.jpg, and <frame>.inputs.json. The JSON holds the system prompt, the parts in order and the focus target.

Open the subject crops in Preview at 100% to see whether a face crop centres on the eyes before you spend anything. In scan, faceless frames have no subject crop, because finding one needs the model. The folder can’t be the shoot folder itself.

--no-review-imagesbool

By default, scan and judge write each frame’s review-sheet thumbnail and subject crop into cull-review/assets while the preview is already decoded. That adds about 2% to a scan and saves review a full decode per frame, minutes on a big shoot. The images take roughly 400 KB per frame. This flag skips them; review renders them when it opens.

--freshbool

Replaces an existing report that holds model assessments. That throws away what you paid for: use -o to write elsewhere instead, unless that is what you mean.

-j, --concurrencyint · default 4

Frames processed in parallel. Each 60 MP preview is decoded once, and peak memory measured 1.9 GB at -j 4 on 992 frames. 17 frames took 12.5 s.

--project, --event, --location, --keyworddeprecated

Set tags with cull offload or cull tag instead. These still work on scan, with a warning, until the next release.

cull judgeAI

Sends each frame to a vision model for assessment, applies the policy, then ranks the sets. Run it again to continue. This is the step that costs money or quota.

cull judge [--backend anthropic|claude-code|openai] [-m MODEL] [--estimate] [--batch] [--fresh] [--rerank] [--sort[=culls]] [--no-xmp] <dir>

Per frame, in order:

1. Extract the full-resolution preview, read EXIF, measure exposure and raw clipping, compute the look, and check for a blank frame. Junk is decided here and never sent. 2. Detect faces. A confident face is the focus target. Without one, a cheap locate call on a 1024 px copy asks the model what was meant to be sharp: the nearest eye for people and animals, otherwise the key detail. 3. Cut the subject crop at native resolution: a 768–1536 px square centred on the eyes, or on the located box plus a 20% margin. 4. Send the evaluate call: the subject crop, a downscaled full frame for context (--max-edge), and a text block of exposure statistics, raw clipping and the camera. 5. Validate the JSON answer against the schema and apply the policy.

What the model returns. It writes its evidence before its verdict, to discourage rationalising:

Sharpness on the crop: sharp (8–10), acceptable (6–7.9), soft (3–5.9), or missed_focus and motion_blur (0–2.9). The prompt warns that fabric, hair and foliage always look crisper than skin. Exposure: good, fixable with an EV between −4 and +4, or clipped. Composition: good, croppable with a suggested crop, or flawed. People: eyes open, closed or partial, and expression. Up to eight lowercase content keywords, which become sidecar keywords. Leica M bodies are described in the prompt as rangefinders, manual focus and often shot wide open, so shallow depth of field isn’t mistaken for a miss.

Then the sets. When every frame of a set is judged, the set is ranked side by side. Each frame is sent as a 768 px view plus a crop of at most 512 px around its focus point. The priorities are subject sharpness, then eyes and expression, then gesture and moment, then composition, then unfixable exposure. Sets of up to 8 take one call. Larger sets are ranked in chunks of up to 8, followed by a final round. Judge ranks the sets that need it at the end of every run, so a run that stopped early ranks the rest next time; --rerank ranks every set again.

Before spending, a priced run prints its estimate, and on a terminal it asks Spend about $X? [y/N] if the estimate exceeds $1. The report is checkpointed every 25 frames, so Ctrl-C or a crash loses little. Run the same command again to continue.

Re-running continues. An existing report is continued, not replaced: frames already judged are skipped, new frames in the folder are picked up, and the backend, model and effort come from the report. --fresh replaces the report.

Examples

$ cull judge --estimate ~/Pictures/"2026-10-02 Smith wedding"
estimate: 612 frames × ~6k in / ~1k out tokens ≈ 3672000 in / 612000 out ≈ $13.46 at list price (claude-sonnet-5-5)
ranking ≈ 77 call(s), $2.31 at list price, if every frame lands in an 8-frame set (pairs cost more per frame; frames in no set cost nothing)
$ cull judge --batch --max-cost 10 ~/Pictures/"2026-10-02 Smith wedding"   # half price; Ctrl-C is safe
$ cull judge --backend claude-code --quota-stop 0.6 --sort ~/Pictures/"2026-10-02 Smith wedding"
$ cull judge ~/Pictures/"2026-10-02 Smith wedding"   # again, after Ctrl-C, a crash, or new frames

Backend and authentication

--backendanthropic | claude-code | openai · default anthropic

The default is anthropic, or what ~/.cull says. Once a shoot is judged, the report’s backend wins over both, until you replace the report with --fresh.

anthropic calls the Messages API with structured output (a JSON schema), and caches the system prompt. 429, 529 and 5xx responses are retried up to five times, honouring retry-after.

claude-code runs claude -p once per call on your Claude subscription. It runs headless in an empty temp folder, with no tools, MCP, settings or session history, and the images go in on stdin. API-key environment variables are removed from the child process. The run aborts before spending anything unless Claude Code reports subscription auth (apiKeySource: none), so it can’t silently bill an API key.

openai posts to any OpenAI-compatible /chat/completions endpoint: llama.cpp, LM Studio, vLLM, Ollama, OpenRouter. It uses a strict JSON schema at temperature 0. It is free on local hardware, but small models judge focus poorly.

With every backend, an answer that fails the schema gets one fresh retry.

$ cull judge --backend openai --base-url http://127.0.0.1:1234/v1 -m qwen2.5-vl-7b-instruct -o local.json ~/Pictures/"2026-10-02 Smith wedding"
-m, --modelstring · default claude-sonnet-5-5 (anthropic), sonnet (claude-code)

Which model judges. It is required for openai. Prices per million tokens, input/output: Sonnet 5.5 $2/$10, Opus 5.5 $4/$20, Haiku 4.5 $1/$5. A model missing from the price table is costed at $0 with a warning, and refused if --max-cost is set.

On claude-code an alias such as sonnet is pinned to the model it resolved to, which is recorded in the report. If Anthropic later moves the alias, a later run stops and asks for the exact ID, rather than mixing two models in one report.

$ cull judge -m claude-opus-5-5 --estimate ~/Pictures/"2026-10-02 Smith wedding"
--api-key-filepath

Reads the Anthropic key from this file; a single KEY=value or export line also works. Without it, the key comes from $ANTHROPIC_API_KEY, then ~/.anthropic/api_key, ~/.config/anthropic/api_key, ~/.anthropic_api_key and ~/.anthropic. A file readable by others gets a warning. The key itself is never printed or logged, only its source.

--base-urlURL · default http://127.0.0.1:8000/v1

The OpenAI-compatible endpoint, up to and including /v1.

--openai-key-filepath

An optional bearer key for the openai backend, for hosted endpoints. Falls back to $OPENAI_API_KEY, else no key.

--openai-streambool · default true

Streams the answer and hangs up as soon as the JSON object closes. Some local servers keep generating after the answer, and streaming halved a two-frame run, from 95 s to 45 s. Use --openai-stream=false for servers with broken streaming.

--claude-binpath · default claude

The Claude Code executable, if it isn’t on PATH.

--effort, --locate-effortlow | medium | high | xhigh | max · default the model's own

Reasoning effort for the evaluate and rank calls, and for locate calls. Escalated evaluations get the same effort. Both are recorded in the report, and a continuing run uses the report’s values; a different one typed against it is refused, so one report never mixes them. Not supported on openai, as the first pass or as the escalation. Measured on claude-code: low saved no output tokens and flipped statuses slightly more often, so the default is left alone.

-j, --concurrencyint · default anthropic 4, claude-code 2, openai 4

Frames in flight. Each holds a decoded 60 MP preview, a few hundred MB. Raise it for the API if your rate limit allows; keep claude-code at 2; use 1 for a local model on a laptop GPU.

Cost and quota

--estimatebool

Prints the estimate and exits. It needs no key and makes no calls. It assumes about 6k input and 1k output tokens per frame, including a share of locate calls, which was measured. Ranking is priced from the sets a scan already found: ranking ≈ N call(s) for M set(s) already found, counted exactly. If there was no scan, it assumes every frame lands in an 8-frame set and errs high. With --batch it prices at 50%.

On a shoot that is already partly judged it prices only the frames still to judge, and says how many are done. With a priced --escalate-backend it adds an upper bound: the price if every frame escalated.

--max-costUSD · default 0 (no limit)

Stops starting new frames once this run has spent this much at list price, or at batch price with --batch. Frames already in flight finish, so a run can overshoot by a few frames. Ranking draws on the same budget. Results are kept: run the command again, with a new limit if you like, to continue.

The budget is per run, so a second run gets the full amount again. A batch can’t be stopped part-way, so with --batch the estimate for unsent frames is checked before submitting.

$ cull judge --max-cost 15 --yes ~/Pictures/"2026-10-02 Smith wedding"
--yesbool

Skips the “Spend about $X?” question, which is asked on a terminal when the estimate is over $1. Without a terminal there is no question, so pair unattended runs with --max-cost.

--batchbool

Uses the Message Batches API, at half price, with results in minutes to hours. Round 1 sends an evaluate request for every frame with a confident face, and a locate request for the rest. Round 2 evaluates the located frames with their crops. A live 3-frame run took about 2 minutes per round. The sets are then ranked as batches too.

Its state lives in cull-report.json.batch.json, so Ctrl-C, a closed lid or a reboot are all safe: cull judge --batch again re-attaches to batches already paid for. It can’t be combined with another backend, --escalate-backend or --second-opinion.

$ cull judge --batch --batch-poll 2m ~/Pictures/"2026-10-02 Smith wedding"   # go to dinner
--batch-pollduration · default 30s

How often a batch’s progress is checked and printed.

--quota-stopfraction 0–1 · default 0.9

For claude-code only. Every claude -p call reports how much of your plan’s 5-hour and 7-day windows is used. Once either reaches this fraction, no new frames start, the frames in flight finish, ranking is skipped, and the run exits with “run judge again later”. Set it lower to leave headroom for the rest of your day.

$ cull judge --backend claude-code --quota-stop 0.5 ~/Pictures/"2026-10-02 Smith wedding"
--checkpointint · default 25

Saves the report every N finished frames, which bounds the paid work a crash can lose. 0 saves only at the end. Not used with --batch, which has its own state file.

What the model is shown

--locatemodel | off · default model

Without a confident face, model spends one small call (capped at 256 output tokens) asking where focus was meant to be. off skips that call: sharpness is then judged from the full frame plus the “where focus landed” tiles. That suits landscapes, where “the subject” is the whole frame.

$ cull judge --locate off ~/Pictures/"2026-09-14 Dolomites"
--face-min-q, --tiles, --landed-with-subject, --min-preview-edge, --max-edge, --raw-clip, --no-review-imagessee scan

The same image-preparation flags as scan, with one difference: --raw-clip defaults to true here, because clipping feeds the policy. --max-edge sets the size of the context frame and so most of the input cost; sharpness never depends on it.

--save-inputsdir

Also writes each evaluate request’s images and prompt to this folder as the run goes; see scan. Use it to audit a surprising verdict: open <frame>.subject.jpg and check what the model actually saw.

Second looks

--second-opinionbool

Asks the same model again about any frame it called soft, missed_focus or motion_blur, typically a minority of frames. If the second answer isn’t also missed focus or motion blur, a cull becomes review. It never creates a cull, only prevents one, so it buys down false culls for one extra call per doubtful frame: 2 of 17 frames on the sample shoot. Sync runs only.

--escalate-backend, --escalate-modelbackend, model

Re-evaluates doubtful frames on a second backend and model, with the same inputs. Use a cheap first pass with a strong second: Sonnet on your subscription, escalating to Opus on the API. The escalated answer replaces the first for the decision, and the first is kept in the report. If they disagree on cull, the frame goes to review.

The estimate includes the escalation’s upper bound, which also counts towards the $1 question, and --max-cost counts every escalation call at its own price. --effort applies to escalated evaluations too.

$ cull judge --backend claude-code --escalate-backend anthropic --escalate-model claude-opus-5-5 --escalate-on missed_focus,motion_blur --max-cost 5 ~/Pictures/"2026-10-02 Smith wedding"
--escalate-onlist · default soft,missed_focus,motion_blur,eyes_closed

The first-pass outcomes that trigger escalation: any of acceptable, soft, missed_focus, motion_blur and eyes_closed.

Continuing and replacing

(no flag needed)default

An existing report is continued. Every frame already assessed is skipped, matched by path, size and modification time to the nanosecond. Frames that errored or whose file changed run again, and new frames dropped into the folder are picked up.

The backend, model and effort default to the report’s. Typing a different one stops with a message naming what would continue the run (drop the flag), --fresh to replace the report, or -o for a separate report. The stored policy, sets, paid rankings and tags carry over.

--freshbool

Replaces a report that already holds assessments, and pays again, judging with --backend (or ~/.cull’s, or the default) rather than the report’s. It is refused while frames are sorted into folders: run cull restore first. Use -o to keep the old report beside it.

Outputs

--no-xmp, --overwrite-xmpbool

Sidecars are written by default, as frames finish, by the same rules as decide. At the end of the run, every frame you labelled, every frame in a set and every frame whose verdict changed after ranking is rewritten, so the sidecars carry your verdicts and stars. --no-xmp writes none. --overwrite-xmp also replaces sidecars cull didn’t write.

--sort[=all|culls]all | culls · default off; bare --sort means all

--sort (or --sort=all) moves frames into keep/, review/ and cull/ once the run ends. --sort=culls moves only the culls, into cull/. That happens even after a quota stop or Ctrl-C. These are the same moves as decide’s, and cull restore undoes them. Write the value with =: --sort culls is refused, so the word is never taken for the folder.

--labels, --no-labelspath, bool

Your labels drive moves and the end-of-run sidecars, as in decide. --no-labels follows the model’s verdicts alone.

--project, --event, --location, --keyworddeprecated

Set tags with cull offload or cull tag instead. These still work on judge, with a warning, until the next release.

Ranking

--rerankbool

Ranks every set again, even sets the model already ranked, and pays again. Use it after re-judging or adding frames, or to get a second opinion from another model with -m. If only the policy changed, cull decide --keep-best N re-applies the stored order for free. With --batch the ranking runs as a batch at half price.

--no-rankbool

Skips the rank calls for this run; the next judge run ranks the sets that need it (or use --rerank). Sets are still formed and ordered by scores (sharpness, then eyes, composition and exposure), and --outranked still applies to that order, labelled “by scores, not compared”.

--rank-twicebool

Ranks each set of up to 8 frames a second time with the order reversed, to cancel the model’s position bias. Only placements both orders agree on count: inside --keep-best in both is best, outside in both is outranked, and anything else is disputed and goes to review. It doubles those calls.

Also accepts every policy flag. On a new shoot the policy comes from the flags. When continuing a report, it comes from the report, with typed flags overriding it.

cull rank

Use cull judge.

Deprecated in v0.2.0: use cull judge, which now ranks the sets that need it at the end of every run (cull judge --rerank ranks every set again, and --batch ranks at half price). cull rank still works, with a warning, until the next release.

cull review

A contact sheet in your browser for labelling, rating and checking at 100%. Every change is saved as you make it.

cull review [--no-xmp] [--sort[=culls]] [--port N] <dir>

review renders cull-review/index.html next to the report and serves it on 127.0.0.1. The images are 1200 px thumbnails plus native-resolution subject crops, in assets/. It then opens your browser. Each frame shows what the model judged, its verdict and its reasons. It works on a scan report too, for labelling before you spend anything on judging.

Every key press is saved immediately. The page posts the change; the server appends a line to cull-labels.jsonl with an fsync, then rewrites that frame’s sidecar. A line looks like this: {"file":"M1103823.DNG","label":"keep","stars":4,"ev":0.7,"at":"2026-10-02T21:14:03-07:00"}. The log is append-only and the last line per file wins, so your history stays readable with grep.

The images are cached. Thumbnails, subject crops and 100% loupe views live in cull-review/assets. scan and judge write the thumbnails and crops while each preview is decoded anyway, so a judged shoot opens without rendering anything. Each image’s name records the file and focus box it was made from: review renders only what is missing or changed, and removes stale images. Sorting into keep/, review/ and cull/ doesn’t invalidate them.

The server is locked to this machine. It listens on 127.0.0.1 only and checks the Host and Origin headers, which defeats DNS rebinding. API calls need a random 128-bit token, which is passed in the URL fragment so it never reaches a server log.

Keys: K, R and C label the frame keep, review or cull, and U clears the label. 1–5 set stars and 0 clears them. Z opens a 100% loupe on the subject: the whole frame, rendered once on demand, which you pan with the arrows or by dragging. S compares the frame’s set side by side at one scale, and 1–9 picks a keeper. N jumps to the next unlabelled frame, and [ and ] step through sets. − and = keep one frame fewer or more from the set’s top of the ranking; the rest of the set is labelled cull. , and . nudge exposure by 0.1 EV, < and > by 0.5, and \ resets it. Exposure is previewed on the page and applied in Capture One by apply-c1 --exposure.

Filters: by verdict; by Unlabelled, Unrated or Disagreements (your label differs from the model’s); and by set members that are keepers or outranked. Disagreements is the fastest way to audit a run.

Examples

$ cull review ~/Pictures/"2026-10-02 Smith wedding"
$ cull review --no-open --port 8800 ~/Pictures/"2026-10-02 Smith wedding"   # e.g. over an SSH tunnel

The log to append to.

--portint · default fixed per report

By default the port is derived from a hash of the report’s path, somewhere from 49152 to 65535, so it stays the same across restarts. The page’s origin therefore stays the same too, and changes queued while the server was down carry over. If that port is busy, it falls back to a random one, with a warning.

0 picks any free port. Each restart issues a new token: reopen the printed URL, and an old tab’s changes wait in its queue until you do.

--no-openbool

Prints the URL without launching a browser. Open it yourself, keeping the #token=… part.

--sort[=all|culls]all | culls · default off

Re-sorts the shoot once, when you stop the server with Ctrl-C: each frame and its sidecar move into keep/, review/ or cull/ by your labels, as cull decide --sort does, using the report’s stored policy. --sort=culls moves only the culls, into cull/. Nothing moves while the page is open, so a frame never leaves a folder while you are still deciding.

If the server ends any other way (the terminal is closed, or the process is killed), nothing moves: run cull decide --sort yourself. Refused on a scan report, which has no verdicts.

$ cull review --sort ~/Pictures/"2026-10-02 Smith wedding"
--outpath · default cull-review beside the report

Where to write index.html and its assets/ folder.

--forcebool

Renders every image again, current or not. Use it after changing how images look, or if one looks wrong.

--preparebool

Fills the image cache and exits, without starting the server. Run it ahead of a review session, for example after copying a shoot with scan --no-review-images, so the sheet opens at once later.

$ cull review --prepare ~/Pictures/"2026-10-02 Smith wedding"
--clear-cachebool

Deletes the sheet’s cached images, leaving anything else in cull-review/assets alone, and exits. With --prepare it then renders them all again. The next review renders whatever is missing, so clearing is always safe; it only costs time.

-j, --concurrencyint · default the number of CPU cores, at most 8

How many images to render in parallel. Each needs about 200 MB, because every one starts from a decoded 60 MP preview. On 17 frames, 8 workers took 1.3 s where 4 took 3.0 s.

Files don’t move while you review. A label change rewrites only the labels log and the frame’s sidecar, where the frame is now: a frame you rescue from cull/ stays in cull/, with a green label, until you re-sort with review --sort or cull decide --sort. Don’t re-sort once keep/ and review/ are imported into Capture One or Lightroom: they lose track of files that move under them. After import, push your changes in with cull apply-c1.

cull import-labels

Use cull review.

Deprecated in v0.2.0: label in the served cull review, which saves every change to the labels log as you make it. cull import-labels still works, with a warning, until the next release.

cull calibrate

Scores reports against your labels, and shows what each combination of policy settings would have done. Free.

cull calibrate [--labels F] <dir|report.json>...
cull calibrate --compare <a.json> <b.json>

For each report it prints the confusion matrix of your label against its verdict, then three rates:

False-cull rate: frames you labelled keep that it culled, out of all your keeps. This is the number to drive towards zero, because a false cull is a lost photograph. Missed-cull rate: frames you labelled cull that it kept. That only costs you a second look. Review rate: the share it handed back to you, which is the price of caution.

It then prints a policy grid: it fully re-decides the stored assessments and ranks under every combination of --keep-best 1–5, --outranked review or cull, and --raw-clipped review or ignore, with the other settings taken from the report’s policy or your flags. Each row shows the false culls (a count and a percentage), the culls caught, the culls missed and the review rate. A * marks rows under 1% false culls, and ← current marks the settings the report holds. Reports with sets also get a sets section: how often a frame you kept was ranked out, and how often a reject was ranked in. A junk line lists any blank-filtered frame you labelled keep.

To adopt a row, run cull decide with its flags, then cull decide --sort when you are happy. Treat a grid tuned on one shoot with care: confirm it on the next labelled shoot before relying on it.

Only verdict labels count; stars alone don’t. The matrix scores each report’s stored verdicts, so to score a new policy, run decide first. Several reports are scored against the same labels, which compares backends or models directly.

Examples

$ cull calibrate ~/Pictures/"2026-10-02 Smith wedding"
$ cull calibrate --labels ~/Pictures/"2026-10-02 Smith wedding"/cull-labels.jsonl sonnet.json local-4b.json   # which backend agrees with you?
$ cull calibrate --compare run1.json run2.json
run1.json vs run2.json: 17 frames in both
decisions agree on 17/17 = 100%
keep↔cull crossings: 0
sharpness status differs on 2/17
mean |Δ sharpness score|: 0.32

Flags

--labelspath · default cull-labels.jsonl beside the first report

The labels to score against.

--comparebool

Takes exactly two reports over the same frames and needs no labels. It prints how often their verdicts agree, the flips between them, keep↔cull crossings (the dangerous kind), sharpness status changes, and the mean score drift.

Run it on two runs of the same backend to measure the noise floor before reading anything into a difference between backends. Verdicts can’t be more trustworthy than they are stable.

Also accepts every policy flag. They set the grid’s other settings and the sets section, not the stored verdicts that the matrix scores.

cull decide

Re-applies the policy to the stored assessments, then rewrites sidecars and, with --sort, moves files to match. No model calls, so it is free.

cull decide [policy flags] [--sort[=culls]] [--no-xmp] <dir>

decide is the tuning loop. It reruns the policy over every assessment in the report, prints how many verdicts changed and saves the report along with the policy it used. Your labels from review then drive the outputs: sidecars, moves and ratings. The report keeps the model’s verdicts.

Without --sort nothing moves: it changes only the report and the sidecars cull wrote (--no-xmp leaves those alone too), so it is safe to try anything. It refuses a scan-only report, which has no assessments to decide.

Examples

$ cull decide --review-below-sharpness 6 --eyes-closed cull ~/Pictures/"2026-10-02 Smith wedding"
policy from the report: --keep-best 2 (a flag on the command line overrides it)
using your labels from …/cull-labels.jsonl (41 frames; --no-labels to ignore)
decided 612 frame(s); changed: keep→review 9, review→cull 2
$ cull decide --sort ~/Pictures/"2026-10-02 Smith wedding"
writing sidecars: 17 files
sorting frames into keep/, review/ and cull/: 17 frames
decided 17 frame(s); no decision changed; sorted 17 into keep/, review/ and cull/, 0 back into the shoot folder

Outputs

--no-xmpbool

Sidecars are on by default (Capture One reads them on import, but ignores develop settings in them): decide writes one for every judged frame, beside wherever the frame is now, and creates any that are missing. It overwrites a sidecar only when cull wrote it: the report records it as cull’s, or it carries cull’s x:xmptk="cull" marker. Anything else is left alone and noted in the report. --no-xmp writes none.

The sidecar uses your verdict and stars where you gave them, and the model’s verdict otherwise.

--overwrite-xmpbool

Also overwrites sidecars that cull didn’t write, such as ones from Lightroom or a previous tool. Their contents are replaced, not merged.

--sort[=all|culls]all | culls · default off; bare --sort means all

--sort (or --sort=all) syncs keep/, review/ and cull/ inside the shoot folder with the current verdicts (yours first). Each DNG moves with its .xmp, by rename on the same disk; a frame whose verdict changed moves between folders. Nothing is ever overwritten or copied, every move is recorded as moved_to, and emptied folders are removed.

--sort=culls is the lighter alternative: only culls move, into cull/. Frames no longer culled come back, including frames an earlier --sort moved, and frames an older version left in its culled folder. Use it to import the shoot folder as it stands, minus the rejects.

Sort before importing: a catalogue loses track of files that move later. Undo with cull restore. Write the value with =: --sort culls is refused.

$ cull decide --sort=culls ~/Pictures/"2026-10-02 Smith wedding"

Labels

--labelspath · default cull-labels.jsonl beside the report

Reads your labels from another log, which must exist. That helps when you labelled a copy of the shoot, or keep logs per client. Frames are matched by file name, so a shoot with two files named L1000123.DNG, from two cards, is refused.

--no-labelsbool

Ignores your labels, so sidecars and moves follow the model alone. Use it to see what the model would have done unsupervised. Can’t be combined with --labels.

Also accepts every policy flag.

The policy flags

The rules that turn the model’s assessments into keep, review or cull. judge, decide and calibrate all accept them.

The model never decides. It reports a sharpness status and score, exposure, composition, eyes and expression. A fixed function in Go then applies these rules, so the same assessments under the same policy always give the same verdicts. Changing a rule never needs a model call: cull decide re-applies it to the stored assessments in a second.

The most severe outcome wins. The order is cull, then review, then keep, and every rule that fires leaves a reason in the report. The rules run in this order:

1. Junk. A blank frame gets the --junk action without an assessment. 2. Sharpness. Missed focus or motion blur culls, soft goes to review, and a low score can raise review. 3. Disagreement. When a second assessment disagrees, a cull is lowered to review; this is the only rule that ever lowers a verdict. 4. Clipping. 5. Eyes. 6. Sets. A frame that would keep but ranks below --keep-best in its set gets --outranked. Composition never culls; at most it adds a note.

The policy is stored in the report. Every later decide, calibrate and judge (continuing the report) starts from it, and a flag you type overrides only its own setting. Stored values that differ from the defaults are printed, for example policy from the report: --keep-best 2 (a flag on the command line overrides it). To go back to a default, type the default value explicitly. A judge --fresh starts again from the flags alone.

Your labels sit above all of this. A verdict you gave in review overrides the policy for sidecars, folder moves and Capture One. The report still keeps the model’s verdict, so calibrate can score it against yours.

Examples

$ cull decide --review-below-sharpness 6.5 --eyes-closed cull ~/Pictures/"2026-10-02 Smith wedding"   # stricter; free, instant
$ cull decide --keep-best 3 ~/Pictures/"2026-10-02 Smith wedding"   # back to the default after tuning

Sharpness

--cull-max-sharpnessfloat 0–10 · default 2.9

A missed_focus or motion_blur status culls only when the sharpness score is at or below this. Above it, the frame goes to review with the reason “scored N (cull needs 2.9 or less)”. The prompt’s score band for those statuses ends at 2.9, so the default is a consistency check: it catches a model that says “missed focus” but scores 5.

0 lets the status cull on its own, whatever the score.

$ cull decide --cull-max-sharpness 2 ~/Pictures/"2026-10-02 Smith wedding"   # cull only clear misses
--review-below-sharpnessfloat 0–10 · default 0 (off)

Sends a sharp or acceptable frame to review when its score falls below this. Use it when “acceptable” isn’t good enough for the job, such as a print client or a tight headshot. soft always goes to review regardless.

The prompt’s bands are sharp 8–10, acceptable 6–7.9 and soft 3–5.9. In repeated runs, acceptable frames scored 6.5–7, so a threshold of 7 reviews most of them. Try it by hand with cull decide; calibrate’s grid covers the set and clipping rules, not this one.

$ cull decide --review-below-sharpness 7 ~/Pictures/"2026-10-02 Smith wedding"

Eyes, clipping, junk

--eyes-closedignore | review | cull · default review

What to do when the model says the subject’s eyes are closed. Half-closed eyes only add a note. Use cull for a portrait session; use ignore for street or landscape, where a closed-eye passer-by shouldn’t matter.

$ cull decide --eyes-closed cull ~/Pictures/"2026-10-02 Smith wedding"
--raw-clippedignore | review | cull · default review

What to do when the share of raw highlight samples at the sensor’s white level reaches --raw-clip-threshold. This is measured from the raw data, not judged by the model; the JPEG preview overstated clipping 4× to 1000× in testing. If the raw wasn’t measured and the model reports clipping, the frame goes to review with “verify against raw”.

--raw-clip-thresholdpercent · default 0.5

The share of raw samples at the white level that counts as clipped. 0.5% is roughly a specular highlight or a patch of white sky. A backlit wedding dress might reach 2%. Raise it if review fills with frames you are happy with.

$ cull decide --raw-clip-threshold 2 ~/Pictures/"2026-10-02 Smith wedding"
--junkcull | review | ignore · default cull

What to do with blank frames, which are detected without a model call:

black: 98% or more of pixels with luma below 16 (lens cap, pocket shot);
white: 95% or more at 255 (a frame shot into the sun);
uniform: a 64 px thumbnail with a standard deviation below 3 (a grey card or a wall).

Junk frames cost nothing and never join a set. ignore judges them anyway. The thresholds come from one photographer’s outdoor portraits: on 992 real frames only the genuinely blank one tripped. For a night-sky or white-seamless shoot, check calibrate’s junk line.

$ cull judge --junk review ~/Pictures/"2026-08-12 Perseids"

Sets and ranking

--keep-bestint 0–5 · default 3

How many of each set’s best-ranked frames keep their verdicts. A frame ranked below that, which would otherwise keep, gets --outranked. Ranking only ever demotes a keep: it never rescues a cull.

0 ranks without demoting anything, though rank 1 is still tagged cull:best. The ceiling is 5 because a large set is ranked in chunks with a final round of at most 8 frames.

$ cull decide --keep-best 1 ~/Pictures/"2026-10-02 Smith wedding"   # one frame per burst
--outrankedignore | review | cull · default review

What happens to a would-be keep ranked below --keep-best. The default is review on purpose: ranking has been measured against labels on only one shoot so far, so confirm cull on your own labelled shoot first. Switch to cull once the sets section and the grid in calibrate show the ranking agrees with you.

$ cull decide --outranked cull ~/Pictures/"2026-10-02 Smith wedding"
--seq-gapduration · default 1m0s

Frames this close in capture time may join the same set; the look test must pass too. 0 turns grouping off. A frame with no capture time is grouped by look alone. Sets are capped at 40 frames.

Durations are Go syntax: 90s, 2m, 1m30s. The M11-P’s EXIF time has 1-second resolution and is only as good as the camera clock, so on a wrong clock the look does the work.

$ cull decide --seq-gap 10s ~/Pictures/"2026-10-02 Smith wedding"   # bursts only, not a whole set-up
--seq-lookfloat 0–1 · default 0.08

The largest “look distance” to the previous frame for a frame to join its set. The look is an 8×8 grid of mean colour, so two takes of the same framing measure about 0.02–0.04, and a new pose at the same spot about 0.12–0.17.

Raising it towards 0.12 starts linking reframed takes, at the risk of merging different poses. A portrait–landscape switch never links, because the grid follows the displayed orientation.

$ cull decide --seq-look 0.11 ~/Pictures/"2026-10-02 Smith wedding"

Crops

--min-crop-areafraction 0–1 · default 0.6

Drops a suggested crop that keeps less than this fraction of the frame. A crop down to 40% of an M11-P frame still leaves 24 MP, but it is rarely what a photographer meant. This is one way: a dropped crop is removed from the stored assessment, so lowering the value later doesn’t bring it back without a re-judge.

$ cull judge --min-crop-area 0.75 ~/Pictures/"2026-10-02 Smith wedding"

cull tag

Shows or changes the shoot’s keywords: project, event, location and extra keywords.

cull tag [--project P] [--event E] [--location L] [--keyword K]... [--clear-*] <dir>

Tags live in the report and go into every frame’s sidecar next to the model’s content keywords. Without flags, tag prints them. offload accepts the same four flags and merges them in the same way, so you can tag the shoot when you copy the card. (On scan and judge they still work, with a warning, and go in the next release.)

Merging. --project, --event and --location each replace only their own field and persist across runs. --keyword is repeatable, and any use of it replaces the whole extra list: to add one keyword, repeat the ones you want to keep. A value containing |, or starting with cull:, is refused, because those are cull’s own separators and namespace.

In the sidecar, the values are added to dc:subject as plain words. Project, event and location are also added to lr:hierarchicalSubject as project|Weddings, event|Ceremony and location|Pittock Mansion, Portland, which Capture One and Lightroom show as nested keywords. Extra keywords stay flat. tag changes the report only; the sidecars pick the tags up on the next cull decide, which rewrites them by default, and cull apply-c1 applies them to frames already in Capture One.

Examples

$ cull tag ~/Pictures/"2026-10-02 Smith wedding"
project: Weddings
event: Ceremony
location: Pittock Mansion, Portland
$ cull tag --keyword leica --keyword "m11-p" --keyword "summilux 35" ~/Pictures/"2026-10-02 Smith wedding"   # sets exactly these three
$ cull tag --event Reception --clear-location ~/Pictures/"2026-10-02 Smith wedding" && cull decide ~/Pictures/"2026-10-02 Smith wedding"

--projectstring

The long-running body of work: a client, a series, a book.

--eventstring

What happened: Ceremony, Fall session, Day 3.

--locationstring

Where, as you would search for it later. EXIF from an M11-P carries no place name.

--keywordstring, repeatable

Extra flat keywords for every frame: gear, client code, licence. Replaces the stored list.

--clear-project, --clear-event, --clear-location, --clear-keywordsbool

Removes one field, or the extra keyword list. An empty value such as --event "" counts as not given, so use these instead.

cull apply-c1

Generates an AppleScript that brings verdicts, keywords, stars and edits into the open Capture One document. It only prints the script unless you add --run.

cull apply-c1 --probe
cull apply-c1 [--exposure] [--crop] [--run] <dir>

Capture One reads a sidecar only when it imports the file. apply-c1 covers what happens after that: labels you changed, tags added later, and exposure, which Capture One ignores in sidecars.

How images are matched: by full path first, using where the frame lives now, even after --sort. Failing that, by file name, then by name without the extension, but only when exactly one image matches. Ambiguous and missing names are listed when the script finishes, never guessed.

What it changes, per variant: the colour tag (green keep, yellow review, red cull), keywords, and stars, but only on frames you rated. A rating you made in Capture One stays. The keywords are cull:keep (or cull:review, cull:cull), cull:labeled, cull:best, the content keywords and your tags. They are applied as plain words, because the AppleScript dictionary can’t set a keyword’s parent.

Examples

$ cull apply-c1 --probe | osascript -   # read-only: the first 5 images, their tags, crops and exposure
$ cull apply-c1 ~/Pictures/"2026-10-02 Smith wedding" > apply.applescript   # dry run: read it first
$ cull apply-c1 --exposure --crop --run ~/Pictures/"2026-10-02 Smith wedding"

What to apply

--labelbool · default true

Sets colour tags: keep 4 (green), review 3 (yellow), cull 1 (red). This numbering is an assumption: check it with --probe on your catalogue first. --label=false leaves tags alone.

--keywordbool · default true

Applies the keywords, creating any that don’t exist yet. --keyword=false skips them.

--ratingbool · default true

Sets stars from your labels, only on frames you starred. It never clears a rating.

--exposurebool

Sets exposure. An EV you chose in review is applied as given. The model’s suggestion for a fixable frame is applied only where exposure is still exactly 0, Capture One’s default, so an edit you already made stays. Unlike sidecar develop settings, this also applies to culls.

Tested on Capture One 16.7.2: setting exposure to 1.0 read back 0.0 → 1.0.

--cropbool

Sets the model’s suggested crop on frames it marked croppable, only where the variant is still uncropped. Whether Capture One measures crops in the same orientation as cull is unverified; if they differ, the check finds the frame “cropped” and skips it, which is the safe failure.

Running

--probebool

Prints a read-only script that lists the first five images in the open document: name, path, dimensions, and each variant’s rating, colour tag, crop and exposure. It needs no folder. Run it first to see how your Capture One names and numbers things.

--runbool

Pipes the script to osascript instead of printing it, and prints the result: done, or the frames it couldn’t find or match uniquely. macOS asks once for permission for your terminal to control Capture One.

--osascriptpath · default osascript

The executable that runs the script.

--labelspath · default cull-labels.jsonl beside the report

Your labels log; your verdicts override the model’s.

--no-labelsbool

Uses the model’s verdicts only, and sets no ratings.

cull restore

Moves every frame that --sort moved back to where it was.

cull restore <dir>

For each frame recorded with moved_to, restore renames the DNG and its sidecar back to the original path. It then removes keep/, review/ and cull/ (and the culled folder that older versions used) if they are empty. A stray .DS_Store keeps a folder. Verdicts are untouched.

It never overwrites. If something now sits at a frame’s original path, that frame stays where it is, is listed, and remains recorded. If you moved a file by hand, restore finds it in the shoot folder or one of those folders, by matching size and modification time, and adopts that location only when exactly one candidate matches.

To keep some culls and restore the rest, move those files back by hand instead, or relabel them in review and run decide --sort again.

Examples

$ cull restore ~/Pictures/"2026-10-02 Smith wedding"
restored 17 frame(s)
